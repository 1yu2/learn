# 附：Q1 完善版答案（先别看，重答后再对照）

**核心原则：先定位瓶颈，再决定补什么。** Agent 的失败有三种类型：

1. **感知瓶颈（看不到）** → 补上下文。模型推理过程没问题但结论错，原因是关键信息不在上下文里
2. **决策瓶颈（看到了但想错）** → 换更强的模型。信息齐全、推理链完整，但逻辑错误、规划不合理
3. **行动瓶颈（想做但做不到）** → 补工具。模型给出正确方案，但没有执行接口

**默认优先补上下文**，三个现实约束：

- **可控性**：模型升级不在应用开发者手里，只能等厂商发版；上下文和工具今天就能改
- **成本**：换模型意味着全链路重新验证（提示词、评估、成本结构都变），补上下文是增量改动
- **分布**：生产失败案例中感知瓶颈占比通常最高——"许多看似需要更聪明模型的问题，其实只是接口问题"

**选择改变的条件**：硬推理任务且确认信息给全 → 换模型；需要对封闭系统产生副作用 → 补工具；模型跨过代际阈值（如非推理→推理模型）时，换模型收益突然变大。

**推论**："定位瓶颈"本身依赖失败轨迹的收集和分析——这属于 Harness 而非模型，所以 Harness 工程才是竞争力。
