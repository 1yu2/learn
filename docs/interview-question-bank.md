# AgentScope 八股题库与掌握度验证

## 评分规则

每题 0-2 分：

- `0`：无法回答，或把 1.x API 与 2.x API 混用。
- `1`：能说出定义，但缺少数据流、边界或失败处理。
- `2`：能结合仓库代码说明设计取舍，并能说出测试或排错方法。

每次自测抽取 12 题，先按 0-24 分记录，再用 `原始分 / 24 * 10` 换算为 10 分制；阶段通过线为 7/10，完整题库至少达到 80%。答错题必须在 48 小时内补一段笔记、一个最小实验和一次复测。

## 题目

### 架构与消息事件

1. **Agent、Model、Toolkit 的职责边界是什么？**
   - 要点：Agent 编排上下文、推理和行动；Model 负责 provider 调用；Toolkit 暴露工具与 schema。
   - 追问：为什么不能把权限校验只放在 system prompt？
2. **`Msg` 和 `Event` 有什么区别？**
   - 要点：Msg 是完整消息/轮次，Event 是流式过程信号；Event 可重建最终消息。
   - 追问：前端为什么更适合消费 Event？
3. **`reply` 和 `reply_stream` 的工程取舍是什么？**
   - 要点：一次性调用简单；流式调用提供进度、工具状态和确认暂停，但需要聚合与恢复。
   - 追问：如何避免重复渲染同一个 block？
4. **`ToolCallBlock` 和 `ToolResultBlock` 如何关联？**
   - 要点：通过 tool call 标识关联调用与结果，不能只按文本顺序猜测。
   - 追问：并发工具返回时如何保证可观测性？

### Model 与结构化输出

5. **Credential、model class、formatter 分别解决什么问题？**
   - 要点：凭据配置、provider 能力封装、内部 Msg 到 provider payload 的转换。
   - 追问：切换 provider 时哪些层应保持不变？
6. **结构化输出为什么要用 schema，而不是让模型输出 JSON 文本？**
   - 要点：schema 提供校验、类型和失败边界；纯文本 JSON 仍可能缺字段或类型错误。
   - 追问：校验失败后应该重试什么，而不是盲目重试什么？
7. **流式 ChatResponse 对上下文有什么影响？**
   - 要点：需要累计增量、处理终止状态，并在持久化前形成完整消息。
   - 追问：中途中断时如何记录可恢复状态？

### Agent、工具与权限

8. **FunctionTool 与 ToolBase 适合什么场景？**
   - 要点：简单纯函数优先 FunctionTool；需要状态、权限或复杂生命周期时用 ToolBase。
   - 追问：工具 schema 如何防止模型传入危险参数？
9. **为什么工具应尽量保持单一职责和可测试？**
   - 要点：减少副作用，便于权限、重试、审计和单元测试。
   - 追问：读文件工具和写文件工具为什么不应合并？
10. **`ALLOW`、`DENY`、`ASK` 的区别是什么？**
    - 要点：允许、拒绝、暂停等待人确认；决策应在工具调用边界发生。
    - 追问：`ASK` 恢复后如何避免重复执行？
11. **为什么不能只靠 prompt 实现安全控制？**
    - 要点：prompt 是软约束，权限系统和工具内部校验才是执行边界。
    - 追问：命令执行工具至少要记录哪些审计字段？

### Plan、Context 与 Middleware

12. **Plan tools 和模型自由文本计划的差异是什么？**
    - 要点：结构化任务有状态、依赖和持久化语义，便于恢复和展示。
    - 追问：什么时候不值得引入 Plan tools？
13. **`pending -> in_progress -> completed` 的状态机为什么重要？**
    - 要点：让任务进度可判断，避免“计划写了但没有执行证据”。
    - 追问：失败任务应新增状态还是记录错误信息？
14. **Context 压缩解决什么问题，会牺牲什么？**
    - 要点：控制 token 和成本；可能丢失细节，因此要保留摘要、最近消息和关键工具结果。
    - 追问：如何测试压缩没有丢失关键约束？
15. **Workspace 与 Context 的边界是什么？**
    - 要点：Context 是工作记忆；Workspace 是文件、offload 和运行状态承载。
    - 追问：多 session 时为什么需要隔离 workspace？
16. **Middleware 适合放哪些横切逻辑？**
    - 要点：耗时、预算、追踪、压缩、长期记忆等；不应把核心业务工具藏在 middleware 中。
    - 追问：middleware 失败时是否应该阻断主流程？

### RAG、记忆与服务化

17. **RAG 的完整数据链路是什么？**
    - 要点：parser -> chunker -> embedding -> vector store -> retrieval -> prompt/context。
    - 追问：召回正确但回答错误，先查哪一段？
18. **chunk size 和 overlap 如何影响检索？**
    - 要点：块过大噪声多，过小缺少语义，overlap 用于减少边界丢失；需用数据验证。
    - 追问：如何设计一个离线检索评测集？
19. **普通 RAG 和 Long-Term Memory 的区别是什么？**
    - 要点：RAG 面向外部知识检索；长期记忆面向跨 session 的用户/任务事实，并需更新与遗忘策略。
    - 追问：哪些内容不应自动写入长期记忆？
20. **Agent Service 为什么要关注 tenant、session 和 workspace 隔离？**
    - 要点：避免数据串扰、权限越界和上下文泄露。
    - 追问：如何用测试证明两个 session 不共享私密状态？
21. **Agent Team 的 leader/worker 边界如何设计？**
    - 要点：leader 分解和汇总，worker 专注子任务；消息协议、超时和失败回传必须明确。
    - 追问：worker 结果冲突时谁负责裁决？

### 工程与安全

22. **为什么离线测试不能用“模型返回正常”代替？**
    - 要点：模型调用不稳定且昂贵；纯函数、配置、权限和事件聚合应确定性验证。
    - 追问：哪些集成测试才值得消耗真实 API？
23. **如何处理模型输出不符合 schema？**
    - 要点：记录原始错误、限制重试次数、修正提示或降级；不能静默吞掉错误。
    - 追问：重试是否会造成重复工具调用？
24. **如何验证 Agent 没有执行未授权写操作？**
    - 要点：工具级权限、沙箱/路径白名单、审计事件和拒绝测试共同证明。
    - 追问：为什么“输出里说没有写入”不是证据？
25. **API key 的配置优先级应该怎样设计？**
    - 要点：进程环境优先，本地 `.env` 作为开发回退，仓库模板不放密钥，日志只打印脱敏摘要。
    - 追问：如何测试日志不会泄露 key？
26. **一个可交付 Agent 项目最低需要哪些文档？**
    - 要点：安装配置、架构数据流、权限边界、运行命令、测试命令、已知限制和故障排查。
    - 追问：怎样把“完成了”变成可复现的证据？
