02
核心定义

工具 = Agent 调用函数去碰外部系统

“Tools are functions Agents call to interact with external systems.” — docs.agno.com/tools/overview（官方原话）

①Python 函数

任意普通函数直接放进 tools 列表零装饰、零包装

②Toolkit 工具包

官方预置 120+ 协同函数集合搜索、金融、数据库、文件…

③MCPTools

把任意 MCP server 的工具挂上来标准化的外部接口

03
自定义工具 · examples/02_tools/02_learn_tool.py

一个普通函数，就是一个工具

def get_current_time() -> str:
    """
    获取当前时间

    Returns:
        str: 当前时间字符串
    """
    from datetime import datetime
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")

# 注册：直接放进 tools 列表
agent = Agent(..., tools=[get_current_time])
  • 不用装饰器、不用继承，函数即工具
  • 函数名、docstring、类型注解都会被 Agno 读取下一页看它们去了哪
  • 返回值建议用字符串 / 数字 / 字典易序列化的结果模型才好消化
04
幕后机制 · 必考

工具 schema 是自动生成的

你写的Agno 生成的 JSON schema模型看到后的作用
函数名name选工具时的名字，要有意义
docstring 正文description判断「什么时候该用它」
docstring 的 Args: 段每个参数的 description判断「该传什么值」
类型注解参数 type；无默认值 → required保证调用格式正确

官方 Tip：写全 docstring 和 Args: 段 —— 文档质量直接决定调用质量。

05
运行机理

工具调用循环 LLM Loop

1

发请求run context + 全部工具 schema 一起发给模型

2

模型决策回复正文，或回复一个/多个 tool call

3

Agno 执行真正运行函数，把结果塞回对话

4

循环直到模型不再发 tool call，输出最终回答

⚠ 关键认知：调不调用，模型说了算

官方措辞是 "when it deems it relevant"（它认为相关时才调）。代码里写了 tools，不代表每次都会用。

06
真实坑 · examples/02_tools/03_tool_example.py

问「15 的平方」，模型可能心算完事

现象

明明给了 calculate_square 工具，模型有时直接答 225，根本不调。

多步任务也一样：04_more_tool.py 每次运行，中间步骤不保证一致。

对策（按顺序试）

① instructions 写死："必须使用工具计算，不得口算"

② 工具描述写清适用场景

③ 还不能容忍 → 别靠概率，走 Workflow 固化（ch6）

「必须调用工具」是提示词约束，不是代码约束 —— 要确定性就得换思路。

07
现成军火库 · examples/02_tools/01_tool_agent.py

Toolkit：一串协同函数的集合

tools=[
    DuckDuckGoTools(
        backend="auto",
        enable_news=False,
        fixed_max_results=5,
    )
],
tool_hooks=[handle_search_errors],
  • 官方定义：一组可加进 Agent、协同工作的函数集合内置 120+ 个 Toolkit
  • 实际注册进 Agent 的工具名是 web_search
  • 注意：DuckDuckGo 只返回摘要，不读网页全文来源和结论要自己核对
08
多工具协作 · examples/02_tools/04_more_tool.py

给一串工具，模型自己排兵布阵

tools=[calculate_square, add, multiply],  # 绑定工具列表

agent.print_response("计算（3—6）*5的结果之后在求平方")
  • 模型自己规划：先减、再乘、最后平方调用顺序由模型生成，不是你写的流程
  • 一次响应可携带多个 tool call
  • 同一句输入，两次运行的中间步骤可能不同这是特性，不是 bug；要稳定流程请等 ch6
09
容错设计 · 你的 05_agentos.py 同款写法

tool_hooks：把异常翻译成模型能懂的话

def handle_search_errors(function_call, arguments):
    try:
        return function_call(**arguments)
    except DDGSException:
        return "搜索未返回结果。请缩短关键词后再次调用 web_search；" \
               "当前调用没有可引用的信息来源。"
  • 包在工具调用外面：拦截异常，返回提示字符串而不是炸掉
  • 模型读到提示后会自己调整关键词重试把「怎么办」的决定权留给模型
  • 可预期的 I/O 错误 → 返回清晰错误信息，是官方推荐的工具写法
10
隐藏通道

内置参数：Agno 偷偷塞给工具的值

声明这个参数工具能拿到什么模型看得到吗
run_context运行上下文；session_state 可读写跨对话状态看不到 —— 从 schema 里剥离
agent / teamAgent 实例本身（如读 agent.instructions）看不到
images / videos / files…本轮输入的媒体文件看不到

它们在执行时由 Agno 注入 —— 模型永远填不了这些参数。

11
性能

并发工具执行的三个前提

  • 用异步入口：arun / aprint_response同步 print_response 下多次调用是顺序执行的
  • 模型支持并行 function calling官方以 OpenAI 的 parallel_tool_calls（默认开）为例
  • 同步函数也能并发：Agno 会把它们放到独立线程上跑

一句话

模型在同一响应里请求多个工具 + 你用了异步入口 = 这些工具同时执行，省的是实打实的等待时间。

12
MCP 速览 · ch1 已见过

MCP 工具的三个冷知识

  • 默认 transport 是 stdio（本地子进程），远程用 streamable-http 或 sse
  • 推荐显式 connect() / close() 管理连接或用 async with；AgentOS 里生命周期自动管理
  • 不管连接的代价：每次 run 都新建/关闭连接并刷新工具列表官方原话：not recommended for production use

回顾 ch1：异步连接必须配 aprint_response，别改回同步。

13
坑与调试 · 你的真实记录

这四颗雷，排掉就是经验

show_tool_calls 不存在了

当前版本 Agent 构造不收这个参数，你的示例已注释掉 —— 别从旧教程里抄回来。

日志写 OpenAI API 是假象

DeepSeek 适配器复用 OpenAI 兼容客户端，报错标题不代表请求去了 OpenAI，先查 key 和网络。

DuckDuckGo 限流

连续请求过快会触发限制，稍后再跑通常比立即狂重试更有效；查询太窄也会 No results。

import 即请求

01–04 示例在模块顶层调模型、顶层校验 key，import 文件就会发请求、烧 token。

14
自测 · 合上书能答几条？

检查点四连问

  • 工具的 JSON schema 是怎么从你的 Python 函数生成的？提示：函数名 / docstring / Args: / 类型注解
  • 什么时候写自定义函数，什么时候直接用 Toolkit？提示：专有逻辑 vs 现成能力
  • 写了 tools=[...]，模型保证每次都调吗？怎么提高必调率？提示：不保证；instructions 写「必须」
  • 多个工具调用什么时候会并发执行？提示：异步入口 + 模型支持并行 function calling
