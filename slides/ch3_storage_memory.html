模型看到历史，需要四个条件同时成立

customer_service_agent = Agent(
    model=DeepSeek(...),
    db=db,
    update_memory_on_run=True,
    add_history_to_context=True,  # ③ 历史放回上下文
    num_history_runs=3,              # ④ 带最近 3 轮
)

# ① 每个用户固定 session_id  ② 固定 user_id
  • ① 稳定的 session_id同一个会话的钥匙
  • ② 稳定的 user_id同一个人的钥匙
  • ③ add_history_to_context=True默认不放回！
  • ④ num_history_runs 控制带几轮默认 3；越多越贵越慢，官方建议从小起步

自动记忆：update_memory_on_run=True

  • 每轮对话后，自动把用户事实与偏好提取进 agno_memories 表"Sarah prefers email" 这类

打错一个字母 = 换了个人

多 Agent 共享一张表 ≠ 自动隔离

class AgentScopedMemoryManager(MemoryManager):
    """只读取当前 Agent 创建的用户记忆。"""

    def read_from_db(self, user_id=None):
        if self.db is None:
            return None
        memories = self.db.get_user_memories(
            user_id=user_id,
            agent_id=self.agent_id,   # ← 强制按 agent 过滤
        )
  • 默认 MemoryManager 读记忆只按 user_id 过滤记录里有 agent_id ≠ 默认会按它过滤
  • 两个 Agent 同库同表同 user_id → 默认共享记忆
  • 覆写 read_from_db() 强制带上 agent_idtests/test_safe_multi_tenant_memory.py 用真实 SQLite 验证过

数据清理的粒度陷阱

操作影响范围什么时候用
db.delete_user_memory(...)单条（需 memory_id + user_id）用户要求删除某条事实
memory_manager.clear()整张表几乎只用于本地重置，生产慎用
换 db_file整个库独立实验之间隔离 —— 你 10 个示例共用一个 my_agent.db 就互相污染过

生产环境必须回答：谁的数据、留多久、怎么删。

cat 10_boundaries.md

记忆的边界，越早知道越好

  • memory 不是权威数据源它是模型生成的摘要，不能替代订单、病历、成绩 —— 那些应该走业务系统
  • 提取是非确定的创建/合并/topics 都有模型参与，别写依赖「一定会记住」的逻辑
  • 记忆会涨，token 也会涨注入上下文的用户记忆持续增长，要定期审视清理
  • history 越多越慢越贵num_history_runs 从 3 起步，不够再加
